# 文游指令创作

## Skill描述

当用户上传参考文游指令或提出文游指令创作需求时，自动触发本Skill。通过学习用户提供的参考文游指令，拆解其结构、逻辑、语气、格式等核心要素，接收用户模糊/具体输出需求，生成贴合参考范式、符合用户要求的文游指令。

核心功能包括：
- **参考指令学习**：分析参考指令的结构模块（场景、角色、规则、任务、反馈、结束条件）、格式规范（标点、换行、人称）、风格特征（古风/现代、简洁/细腻）
- **需求接收处理**：将用户模糊需求（如"来个古风江湖场景"）转化为标准化创作参数，处理具体需求（明确场景、角色、风格等）
- **指令生成输出**：结合学习到的范式库和用户需求，生成可直接使用的文游指令，支持优化反馈循环

适用于文字游戏开发、AI角色扮演场景设计、互动小说创作等场景。

---

## 使用说明

### 触发条件

本Skill在以下场景自动触发：
1. 用户上传参考文游指令文档/文本
2. 用户提出"创作/生成/写文游指令"
3. 用户提及"文字游戏指令"、"AI角色扮演场景"、"互动小说设定"
4. 用户提供具体需求如"来个古风场景"、"帮我设计校园剧情"

### 使用流程

**步骤1：提供参考指令（可选）**
用户可以：
- 粘贴1个或多个参考文游指令文本
- 描述参考指令的特征（"我想要类似XXX那样的风格"）
- 跳过此步骤，直接提出创作需求

**步骤2：提出创作需求**
用户可以用两种方式告知需求：

*模糊需求示例*：
- "来个古风江湖场景，主角是个侠客"
- "我要校园现代风格的，关于学生会竞选"
- "设计一个悬疑推理的开局"

*具体需求示例*：
- "场景：古代客栈；角色：神秘剑客；风格：武侠；指令类型：开局"
- "场景：现代大学校园；角色：转学生；任务目标：融入班级；风格：青春"

**步骤3：生成并优化**
系统会：
1. 分析参考指令（如有），提取范式库
2. 解析用户需求，转化为创作参数
3. 生成文游指令初稿
4. 用户可提出修改需求（如"场景换成雨天"、"角色改成女性"）
5. 系统根据反馈优化指令

## 核心模块说明

### 模块1：参考指令学习

分析参考指令，提取以下范式：

**结构范式**：
- 模块组成：识别是否包含【场景】【角色】【操作规则】【任务目标】【反馈机制】【结束条件】
- 排列顺序：记录模块出现顺序
- 篇幅占比：各模块内容长度

**格式范式**：
- 标点规范：引号用法、序号/项目符号格式
- 换行规则：段落分隔、模块间空行
- 特殊标识：加粗、斜体、颜色标记等
- 人称使用：第二人称（你）/第三人称

**风格范式**：
- 语言风格：古风（江湖、仙侠）、现代（校园、都市）、通用
- 语气特征：简洁干练（短句为主）/细腻氛围（描写丰富）
- 逻辑链条：场景→角色→任务→操作→反馈 或其他组合

**多参考处理**：
- 提取多个参考指令的共性模块
- 标注差异部分，提示用户确认优先级

### 模块2：需求接收与转化

**模糊需求识别**：
系统自动识别关键词：
- 风格关键词：古风、江湖、现代、校园、悬疑、仙侠
- 场景关键词：场景、地点、背景
- 角色关键词：角色、主角、NPC、人物
- 类型关键词：开局、日常、战斗、解谜、对话

**具体需求解析**：
提取明确参数：
- scene: 场景描述
- role: 角色设定
- instruction_type: 指令用途（开局/日常/战斗等）
- style_adjust: 风格调整
- special_require: 特殊要求

**模糊处理策略**：
当需求过于模糊无法识别时，系统会追问：
> "请补充以下关键信息：
> 1. 文游场景（如古风客栈、现代校园）
> 2. 指令用途（可选，如开局/日常/战斗）
> 3. 其他特殊要求（可选）"

### 模块3：指令生成与优化

**生成逻辑**：
1. 根据结构范式搭建框架，保留参考指令的模块顺序
2. 根据用户需求填充内容，缺失部分使用参考范式默认值
3. 根据风格范式调整语言风格（古风替换现代词汇、调整句式）
4. 进行合规校验，确保必要模块存在

**优化循环**：
- 用户可提出修改："场景换成雨夜"、"角色改成女侠"、"增加战斗规则"
- 系统根据修改需求局部替换，保持其他内容不变
- 每次修改后重新校验范式合规性
- 支持多次迭代直到用户满意

## 输出格式

生成的文游指令采用标准模块化结构：

```
【场景】
[场景描述，贴合参考范式的描写风格]

【角色】
[角色设定，包含身份、性格、目标等]

【操作规则】（如参考包含）
1. [规则1]
2. [规则2]
...

【任务目标】（如参考包含）
[任务描述]

【反馈机制】（如参考包含）
[操作后的反馈逻辑]

【结束条件】（如参考包含）
[指令终止条件]
```

## 示例

### 示例1：古风江湖开局指令

**用户输入**：
参考指令：[一个包含【场景】【角色】【操作规则】【任务目标】的古风文游指令]
需求：古风江湖场景，主角是剑客，开局指令

**生成结果**：
```
【场景】
夜色笼罩下的江南小镇，细雨如丝。青石板路上倒映着昏黄的灯笼光，远处传来几声犬吠。你站在一家破旧的客栈门前，手中长剑在雨中泛着寒光。

【角色】
你是一名行走江湖的剑客，剑法凌厉，性情孤傲。三日前收到一封密信，信中提到小镇上藏着一桩关乎武林安危的秘密。你的目标是查明真相，但身份不可暴露。

【操作规则】
1. 每次行动前，请说明你的动作和目的
2. 可使用「调查」「对话」「潜行」「战斗」四种基础行动
3. 与其他角色对话时，请使用引号标注
4. 当体力值低于30%时，必须寻找安全地点恢复

【任务目标】
在三个时辰内找到密信中提到的"红玉扳指"，并查明它与武林盟主失踪案的关联。注意隐藏身份，避免引起镇中眼线怀疑。
```

### 示例2：现代校园日常指令

**用户输入**：
需求：现代校园场景，角色是转学生，融入班级

**生成结果**：
```
【场景】
阳光明媚的九月早晨，你站在育才高中二年三班的教室门口。教室里传来阵阵喧闹声，黑板上还留着上节课的数学公式。班主任李老师正在和班长低声交谈。

【角色】
你是今天刚转来的新同学林晓，性格内向但成绩优异。因为父母工作调动，你从外地转学到这里。你希望能尽快融入新班级，但同时担心自己的口音和穿着会被同学嘲笑。

【操作规则】
1. 可选择「自我介绍」「观察同学」「参与对话」「寻求帮助」等行动
2. 与其他角色对话时使用引号
3. 每次行动后，我会描述周围人的反应和你的心情变化
4. 注意把握时机，不要过于主动或过于被动

【任务目标】
在一天内记住至少5位同学的名字，并找到一位可以一起吃饭的朋友。

【反馈机制】
- 主动交流：同学态度从陌生到友好（进度+20%）
- 帮助同学：获得信任和感谢（进度+15%）
- 表现优异：被老师表扬（进度+10%，但可能引起个别同学嫉妒）
- 行动失误：被误解或冷落（进度-10%）
```

## 规则与容错

### 学习规则
- 用户上传多个参考指令时，优先提取共性范式，差异部分提示用户确认
- 参考指令格式混乱时，自动提取可识别模块，提示用户补充完善
- 永久记忆用户上传的参考范式，除非用户主动触发"清除范式"

### 需求适配规则
- 用户需求与参考范式冲突时，优先遵循用户需求，同时提示冲突点
- 模糊需求无法识别时，触发追问而非随意生成
- 需求缺失关键参数时，使用参考范式默认值或通用模板

### 输出规则
- 最终指令需标注参考范式来源（如有）
- 生成后主动提示用户可以提出修改需求
- 支持多次迭代优化，直到用户确认满意

### 容错机制
- **参考指令为空/不清晰**：提示"参考指令内容不清晰，请提供有效参考后重试"
- **需求无法识别**：提示"请明确需求方向（如场景、角色、风格等）"
- **生成异常**：提示"指令生成失败，请检查参考指令和需求后重试"

---

## 注意事项

1. **参考指令质量影响输出质量**：提供的参考越清晰、结构越完整，生成的指令越贴合需求
2. **风格一致性**：如果参考指令是古风，生成的指令也会采用古风风格
3. **模块灵活性**：并非所有指令都需要全部模块，系统会根据参考范式自动调整
4. **迭代优化**：鼓励用户提供反馈进行多轮优化，单次生成可能无法完全满足复杂需求
5. **版权说明**：请确保提供的参考指令不侵犯他人版权，系统仅用于学习范式而非复制内容
